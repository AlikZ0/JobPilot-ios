# JobPilot 1.0.2 — исправление запуска в уменьшенном режиме iPhone

## Как проявлялась ошибка

На скриншотах приложения большие чёрные полосы сверху и снизу, при этом и контент, и Tab Bar занимают центральную полосу экрана. Пропорции напоминают старый 3.5-дюймовый режим совместимости iOS (320×480) вместо нативного размера современного iPhone.

## Почему предыдущая правка не решила проблему

В `Info.plist` был `<key>UILaunchScreen</key><dict/>`, но в XcodeGen `project.yml` ключ запуска отсутствовал в `targets.JobPilot.info.properties`. XcodeGen генерирует `Info.plist` при каждой сборке и может перезаписать файл на диске. Исправление стилей SwiftUI не решает режим совместимости, если в итоговом IPA нет работающей конфигурации launch screen.

Это вероятная причина по скриншотам и конфигурации исходников, а не доказанный анализ ранее установленного IPA.

## Что изменено

- `project.yml`: добавлены `info.properties`, включая `UILaunchStoryboardName: LaunchScreen`; это основной источник настроек при генерации XcodeGen.
- `JobPilot/LaunchScreen.storyboard`: полноценный адаптивный launch screen со стандартным фоном iOS.
- `JobPilot/Info.plist`: тот же ключ запуска для согласованности исходников; версия 1.0.2, сборка 3.
- `.github/workflows/main.yml`: проверка `Info.plist` после `xcodegen`, а затем в готовом `.app`; проверка существования скомпилированного `LaunchScreen.storyboardc`. Если файл не попал в приложение, workflow завершится ошибкой до упаковки IPA.
- `JobPilot/Views/Settings/SettingsView.swift`: отображение версии 1.0.2 в разделе «О приложении», чтобы отличать новую установку от старой.

Модели данных, Bundle ID, база SwiftData, функции вакансий и карточек не менялись.

## Обновление в GitHub

1. Сделай JSON-экспорт данных в текущем JobPilot, если уже есть вакансии.
2. Распакуй ZIP-патч и замени файлы в репозитории, сохраняя пути и новую папку `.github`.
3. Сделай commit в `main`.
4. Открой GitHub Actions: в job должны успешно пройти шаги `Verify generated launch-screen configuration` и `Verify full-screen launch metadata in compiled app`.
5. Скачай артефакт **нового** запуска Actions, подпиши новый `JobPilot-unsigned.ipa` и установи через SideStore/AltStore поверх старого (если позволяет инструмент и используется прежний Bundle ID).
6. Открой «Настройки» → «О приложении». Должно отображаться **1.0.2**.
7. Проверь, исчезли ли чёрные поля, занимает ли UI весь дисплей и прилегает ли нижняя панель к нижней Safe Area.

Если после установки новой IPA чёрные поля остались, в первую очередь проверь, действительно ли установлена версия 1.0.2. iOS может кэшировать экран запуска. **Не удаляй приложение, пока не экспортировал JSON**, иначе можно потерять локальную базу. После резервной копии и при необходимости можно удалить старую установку и поставить новую с восстановлением JSON.

## Проверки выполнены

- YAML `project.yml` и workflow разбираются без ошибок.
- XML `Info.plist` и `LaunchScreen.storyboard` корректен.
- Синтаксис Swift файлов проверен через `swiftc -frontend -parse`.
- Согласованность ключа `UILaunchStoryboardName: LaunchScreen` проверена.

Полный `xcodebuild archive` и запуск на iPhone здесь не выполнялись; это нужно проверить через GitHub Actions и устройство.
